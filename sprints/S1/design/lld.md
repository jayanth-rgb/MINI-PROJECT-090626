# Low-Level Design — Sprint S1
> Generated by `/ases-lld` · 2026-06-09 · Source of truth: `lld.json`

**Sprint goal (from roadmap):** Data Foundation — 6 master tables + CRUD admin screens + soft delete + seed data + PostgreSQL schema + Alembic baseline.
**Scope modules:** M-001 (Master Data Management), M-007 (Persistence & Migrations)
**Scope features:** F-001..F-006
**API base path:** `/api/v1`

---

## Architecture at a glance

```
                            Next.js (App Router)
  app/admin/<entity>/page.tsx ── shadcn Dialog ── react-hook-form + zod
        │                              │
        ▼                              ▼
  lib/api/masters.ts ───▶  apiClient (axios) ──HTTP──▶ FastAPI /api/v1
                                                            │
                                                            ▼
                                              presentation/api/routers/*.py
                                                            │
                                                            ▼
                                              application/services/*.py
                                                            │
                                                            ▼
                                          infrastructure/db/repositories/*.py
                                                            │
                                                            ▼
                                              SQLAlchemy ORM (Base.metadata)
                                                            │
                                                            ▼
                                                PostgreSQL 16 (Docker)
```

**Layered backend** (presentation / application / domain / infrastructure) per DS-007. Each layer depends only on layers below it. No layer skipping — routers must go through services.

## Backend — 4. Application services

Six service classes — `SupplierService`, `StaffService`, `DealerService`, `GradeService`, `DesignService`, `DesignGradeMapService`. Each owns the transactional boundary (commits the session after a successful write).

Common method shape:
```
list_<entity>(include_inactive=False) → list[<Entity>Read]
create_<entity>(payload: <Entity>Create)  → <Entity>Read
update_<entity>(id, patch: <Entity>Update) → <Entity>Read
deactivate_<entity>(id)                    → <Entity>Read
```

Entity-specific extras:
- `GradeService.create_grade` → 409 `ConflictError` on duplicate `grade_code` (AC-011).
- `DesignGradeMapService.list_active_grades_for_design(design_id)` — minimal projection `{grade_id, grade_code}` for the M-001/HLD DF-006 read contract that S2 transaction forms will consume.
- `DesignGradeMapService.create_mapping` → 409 on duplicate `(design_id, grade_id)`; 404 if either FK is missing.

All services depend on `repositories/master.py`, `presentation/schemas/master.py`, `domain/exceptions.py`.

## Backend — 5. Presentation

### `backend/src/presentation/schemas/master.py`
Pydantic v2 schemas (Create / Update / Read) for the 6 entities + `DesignGradeReadMin` for the active-grades projection. All `Read` schemas set `model_config = ConfigDict(from_attributes=True)`.

| Group | Schemas |
|---|---|
| Supplier | `SupplierCreate` (name+place required), `SupplierUpdate`, `SupplierRead` |
| Staff | `StaffCreate` (name required), `StaffUpdate`, `StaffRead` |
| Dealer | `DealerCreate` (name+place required), `DealerUpdate`, `DealerRead` |
| Grade | `GradeCreate` (grade_code required), `GradeUpdate`, `GradeRead` |
| Design | `DesignCreate` (size+name required), `DesignUpdate`, `DesignRead` |
| DesignGradeMap | `…Create` (design_id+grade_id), `…Update`, `…Read` (with `design_name` + `grade_code` joined) |
| Minimal projection | `DesignGradeReadMin = {grade_id: int, grade_code: str}` |

### `backend/src/presentation/api/dependencies.py`
FastAPI `Depends` providers: `get_db` re-export + one `get_<entity>_service` per service. Each provider wires `Session → Repository → Service`.

### `backend/src/presentation/api/errors.py`
`register_error_handlers(app)` attaches the exception-handler decorators that map `DomainError` subclasses + `IntegrityError` to HTTP responses.

### `backend/src/presentation/api/routers/*.py`
Six routers — one per entity — all with the same shape:

| Method | Path | Handler | Status |
|---|---|---|---|
| GET | `/<entity>` | `list_<entity>(include_inactive=False)` | 200 |
| POST | `/<entity>` | `create_<entity>(payload)` | 201 |
| PATCH | `/<entity>/{id}` | `update_<entity>(id, payload)` | 200 |
| DELETE | `/<entity>/{id}` | `delete_<entity>(id)` — soft delete (DS-008) | 200 |

**Extra endpoint on `designs.py`:**
- `GET /designs/{design_id}/grades` → `list[DesignGradeReadMin]` (AC-019, HLD DF-006). Wires to `DesignGradeMapService.list_active_grades_for_design`.

### `backend/src/main.py`
```
app = create_app()  # FastAPI + CORS + handlers + 6 routers under /api/v1 + GET /health
```
Run: `uvicorn src.main:app --reload` (PowerShell from `backend/`).

## Backend — 6. Migrations & seed

### `backend/db/migrations/env.py`
Standard Alembic env wired to `settings.database_url` and `target_metadata = Base.metadata`. Imports `infrastructure/db/models/master.py` so all 6 models register against `Base.metadata` before autogenerate runs.

### `backend/db/migrations/versions/0002_master_tables.py`
**First real migration.** Created via `alembic revision --autogenerate -m "master tables"` after the ORM models are committed. The autogenerated DDL is reviewed against this LLD before commit. Creates the 6 tables, FKs (`design_id`, `grade_id`), `UNIQUE(grade_code)`, `UNIQUE(design_id, grade_id)`, `INDEX(is_active)` per table.

### `backend/scripts/seed_master_data.py`
Idempotent. Inserts the sample-PRD data per AC-003 / AC-006 / AC-009 / AC-010 / AC-014 / AC-018. Single transaction. CLI entry: `python -m scripts.seed_master_data` from `backend/`.

## Frontend — 4. Per-entity admin pages

Same pattern across all six:
```
useQuery(['<entity>'], <entity>Api.list)
useMutation create / update / remove → invalidate queries on success
MasterDataTable + MasterFormDialog + <Entity>Form
toast.error on API 4xx (surfaces 409 from grade duplicate & design-grade-map duplicate)
```

| Page | Form component | AC coverage |
|---|---|---|
| `app/admin/suppliers/page.tsx` | `SupplierForm` | AC-001, AC-002 |
| `app/admin/staff/page.tsx` | `StaffForm` | AC-004, AC-005 |
| `app/admin/dealers/page.tsx` | `DealerForm` | AC-007, AC-008 |
| `app/admin/grades/page.tsx` | `GradeForm` | AC-011, AC-012 |
| `app/admin/designs/page.tsx` | `DesignForm` | AC-013, AC-015 |
| `app/admin/design-grade-map/page.tsx` | `DesignGradeMapForm` (two Selects) | AC-016, AC-017, AC-019* |

*AC-019 is delivered by the backend endpoint; the admin UI does not consume it (S2 transaction forms do).

Each per-entity form uses `useForm({ resolver: zodResolver(<entity>Schema), defaultValues })` and exposes a stable `formId` so `MasterFormDialog`'s Save button triggers `<form id={formId}>` submit.
