## 2. Form & Field Specs (summary)

| Form | Key behaviours |
|---|---|
| **Inward** (§2.1) | Date max=today, min=today-7d. Supplier → Place auto-fill read-only. Design selection triggers grade row auto-population from `tbl_design_grade_map`. NOS integer > 0; blank/zero rows skipped. |
| **Sales** (§2.2) | Same date and design rules as Inward. Dealer → Place auto-fill. Loading Staff + Verified By both required. Can add multiple design lines. |
| **Adjustment** (§2.3) | Single design per entry. Stock Date <= Entry Date. Software CB auto-pulled per grade as of `stock_date`. Physical CB integer >= 0 (zero valid). Difference computed live. |
| **Dashboard** (§2.4) | Date filter → Opening, Inward, Outward, Adjust, Closing per (design, grade) per FORMULA-001. |
| **Sales Report** (§2.5) | All filters multi-select and optional. Consolidation (GROUP BY design+grade) shown above Transaction (per-line) — always together, never as tabs. |

## 5. Workflow / State Transitions
Documented per form: Empty → Header Complete → Grade Rows Rendered → Data Entry In Progress → Saved → Stock Ledger Updated. Adjustment substitutes "Grade Rows Auto-Populated → Difference Computed Live → Saved → Stock Ledger Adjusted". Sales Report toggles between Default View / Filtered View based on filter presence.

## 8. Stock Formulas

```
FORMULA-001  Closing Balance (Date D, Design X, Grade G) =
             Opening Balance of current month (X, G)
           + SUM(inward.nos WHERE date <= D AND design=X AND grade=G)
           - SUM(sales.nos  WHERE date <= D AND design=X AND grade=G)
          +/- SUM(adjust.difference WHERE stock_date <= D AND design=X AND grade=G)

FORMULA-002  Opening Balance (Month M, X, G) =
             IF no prior month data → 0
             ELSE Closing Balance (last day of M-1, X, G)

FORMULA-003  Difference = physical_cb − software_cb   (+/-)

FORMULA-004  Sales Report Consolidation
             SELECT design_name, grade_code, SUM(nos) AS total_numbers
             FROM tbl_sales_lines sl
             JOIN tbl_sales_header sh ON sl.sales_id = sh.sales_id
             JOIN tbl_trading_design_master d ON sl.design_id = d.design_id
             JOIN tbl_grade_master g ON sl.grade_id = g.grade_id
             [optional WHERE clauses on date / dealer / design]
             GROUP BY sl.design_id, sl.grade_id
             ORDER BY design_name ASC, grade_code ASC;
```

The ASES implementation **stores `running_balance` in `tbl_stock_ledger` per write**, so FORMULA-001 becomes "read the latest `tbl_stock_ledger.running_balance` row WHERE `(design_id, grade_id)` AND `txn_date <= D`". The math is identical; storage form is materialised, not computed each read.
