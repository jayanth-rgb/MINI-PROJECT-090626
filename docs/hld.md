# High-Level Design — Jayanth Trading Tiles System

> Generated by `/ases-hld` · 2026-06-09
> Imported from: uploaded HLD v2.0 (Trading Tiles Module) + technical decisions from stack confirmation

## System Overview

Three-tier monolith:

```
Next.js 15 (App Router, React 19)   ←  Browser
        │  HTTP/JSON
        ▼
FastAPI (Python 3.11)
  ├─ Presentation: routers (HTTP layer)
  ├─ Application: services (use-cases)
  ├─ Domain:      pure functions (stock math, carry-forward)
  └─ Infrastructure: SQLAlchemy repositories + Alembic
        │  asyncpg / psycopg
        ▼
PostgreSQL 16
  (6 master tables + 6 transaction tables + 1 stock_ledger)
```

**Transactional integrity:** All transactional writes (Inward, Sales, Adjustment) and their resulting `stock_ledger` updates run in a single SQLAlchemy DB transaction with `SELECT FOR UPDATE` locks on the affected ledger rows.

**Reads:** The Sales Report and Stock Dashboard read from a materialised `stock_ledger` table storing the running balance per `(design, grade, txn_date)`. Month-end carry-forward is a deterministic lookup of the previous month's last-day closing balance — **no scheduled job needed**.

**Security:** No authentication in V1; deployment is via Docker images on a trusted internal network.

## Modules

| ID | Name | Layer | Responsibility |
|---|---|---|---|
| M-001 | Master Data Management | application | CRUD for all 6 masters; serves active-only feeds |
| M-002 | Transaction Forms | application | Inward / Sales / Adjustment persistence in a single DB txn |
| M-003 | Stock Ledger | domain | Running balance per (design, grade, date); carry-forward |
| M-004 | Stock Dashboard | application | Date-filtered Opening/Inward/Outward/Adjust/Closing read |
| M-005 | Sales Reporting | application | Consolidation + Transaction views with multi-select filters |
| M-006 | Frontend Application | presentation | Next.js admin, transaction forms, dashboard, sales report |
| M-007 | Persistence & Migrations | infrastructure | SQLAlchemy models + Alembic migrations + seed scripts |

### Key Interfaces

**M-001 Master Data**
- `GET/POST/PATCH /suppliers /staff /dealers /grades /designs /design-grade-map`
- `GET /designs/{id}/grades` — active mappings for a design

**M-002 Transaction Forms**
- `POST /inward`, `POST /sales`, `POST /adjustments`
- `GET /designs/{id}/grades-with-cb?stock_date=…` — for Adjustment Form

**M-003 Stock Ledger (domain functions, not HTTP)**
- `apply_inward / apply_sale / apply_adjustment (design_id, grade_id, date, qty)`
- `closing_balance / opening_balance (design_id, grade_id, date) → int`

**M-004 Dashboard**
- `GET /dashboard?as_of_date=YYYY-MM-DD`

**M-005 Reports**
- `GET /reports/sales?date_from=…&date_to=…&dealer_ids=…&places=…&design_ids=…`

## Risk Register

| ID | Risk | Severity | Mitigation | Module |
|---|---|---|---|---|
| R-001 | Concurrent saves on same (design, grade) ledger row race and corrupt balances | **critical** | `SELECT FOR UPDATE` on latest ledger row per (design, grade) before write (DS-002) | M-003 |
| R-002 | Dashboard live SUM gets slow at scale | medium | Read from materialised `stock_ledger` running-balance table (DS-003) | M-004 |
| R-003 | Back-dated 7-day txn into a previous month invalidates its closing | medium | Ledger writes recompute running balance from inserted row forward within same DB txn | M-003 |
| R-004 | V1 has no authentication | medium | Trusted internal network only; documented V1 limit; V2 adds auth (DS-005) | M-006 |
| R-005 | Deactivating a Design-Grade mapping with existing transactions could break reports | low | Soft-delete only; reports JOIN on FK and display historical grade_code; forms filter by is_active | M-001 |

## Architectural Decisions

See `.ases/decisions.json` for full ADR text. Summary:

- **DS-001** — Stack: FastAPI + Next.js + PostgreSQL + Docker (PO-confirmed)
- **DS-002** — Stock ledger writes use SELECT FOR UPDATE on `(design_id, grade_id)` for serialization
- **DS-003** — Materialised `stock_ledger` running-balance table over live SUM
- **DS-004** — Month-end carry-forward as deterministic lookup, not a scheduled job
- **DS-005** — V1 ships with no authentication; defer to V2
- **DS-006** — Frontend and backend are two separate Docker images, not bundled
