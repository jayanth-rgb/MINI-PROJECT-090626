## F-001 — Supplier Master
**Sprint:** S1 · **Priority:** critical

CRUD admin screen for suppliers (name, place). Soft delete via `is_active`. Active suppliers feed the Inward Form dropdown.

- **AC-001** Admin can create a supplier with name and place; both are required.
- **AC-002** Admin can edit and soft-delete (`is_active=false`) a supplier; soft-deleted suppliers do not appear in the Inward Form dropdown.
- **AC-003** Seed data loads: Manjunatha/Mallur, Dinnesh Reddy/Mallur, Antony Tiles/Kerala.

## F-002 — Staff Master
**Sprint:** S1 · **Priority:** critical

CRUD admin screen for staff. Active staff feed dropdowns across Inward, Sales, Adjustment forms.

- **AC-004** Admin can create staff with name; `staff_name` is required.
- **AC-005** Admin can soft-delete a staff member; soft-deleted staff do not appear in any transaction form dropdown.
- **AC-006** Seed data loads 9 staff: Chandran, Jayapal, Ramachandraiah, Sujatha, Ramya, Vijay, Sajil, Ashu, Amaresh.

## F-003 — Dealer Master
**Sprint:** S1 · **Priority:** critical

CRUD admin screen for dealers (name, place). Active dealers feed Sales Form dropdown and Sales Report filter.

- **AC-007** Admin can create a dealer with name and place; both are required.
- **AC-008** Admin can soft-delete a dealer; soft-deleted dealers do not appear in the Sales Form dropdown or report filter.
- **AC-009** Seed data loads: Raj Hardwares/Dindivanam, Tiles Mart/Attibelle, Shanmugam & Co/Coimbatore.

## F-004 — Grade Master
**Sprint:** S1 · **Priority:** critical

Maintains the canonical 9 grades. Read-mostly; seeded at install.

- **AC-010** Seed data loads exactly 9 grade codes: 1, 2, 2A, 4, 5, 6, 1OB, OB, DIM.
- **AC-011** `grade_code` is UNIQUE in the database.
- **AC-012** Admin can deactivate a grade via `is_active=false`; deactivated grades disappear from Design-Grade combinations.

## F-005 — Trading Size-Design Master
**Sprint:** S1 · **Priority:** critical

CRUD admin screen for traded tile designs (size, design_name). Separate from any manufactured-tile design list.

- **AC-013** Admin can create a design with size and design_name; both are required.
- **AC-014** Seed data loads: 16X10 / 16X10 Ridges, 12X8 / 12X8 Ridges, 11X7 / 11X7 Ridges.
- **AC-015** Soft-deleted designs do not appear in the Inward, Sales, or Adjustment form design dropdowns.

## F-006 — Tile Design-Grade Combination Table
**Sprint:** S1 · **Priority:** critical

Maps each design to its valid grades. Drives grade-row auto-population on Inward, Sales, and Adjustment forms.

- **AC-016** Admin can map a (design_id, grade_id) combination with a UNIQUE constraint preventing duplicates.
- **AC-017** Admin can deactivate a combination via `is_active=false` without deleting; historical transactions remain unaffected.
- **AC-018** Seed data loads the 6 combinations: 16X10 Ridges{1,2}, 12X8 Ridges{1,OB}, 11X7 Ridges{1,2}.
- **AC-019** `GET /designs/{id}/grades` returns only `is_active=true` combinations for the design.

## F-007 — Trading Tiles Inward Form
**Sprint:** S2 · **Priority:** critical

Records tile purchases. Selecting a design auto-renders one row per valid active grade.

- **AC-020** Form blocks save when `purchase_date > today` (ERR-001).
- **AC-021** Form blocks save when `purchase_date < today - 7 days` (ERR-002).
- **AC-022** Selecting a supplier auto-populates place from `tbl_supplier_master` read-only.
- **AC-023** Selecting a design queries `tbl_design_grade_map` and renders one grade row per active mapping; grade label not user-editable.
- **AC-024** NOS must be integer > 0; decimals and zero rejected (ERR-007).
- **AC-025** Grade rows where NOS is blank or zero are silently skipped at save (RULE-017).
- **AC-026** Save requires at least one design line with at least one grade row NOS > 0 (RULE-015 / ERR-006 / ERR-008).
- **AC-027** On save, header + valid lines persist atomically and stock ledger increases per (design, grade, purchase_date).

## F-008 — Trading Tiles Sales Form
**Sprint:** S2 · **Priority:** critical

Records sales / dispatch to dealers. Grade-row auto-population identical to Inward.

- **AC-028** Form blocks save when `sales_date` is in the future or > 7 days prior (ERR-001 / ERR-002).
- **AC-029** Selecting a dealer auto-populates place from `tbl_dealer_master` read-only.
- **AC-030** Both `loading_staff_id` and `verified_by_id` are required; both from active staff only.
- **AC-031** Design selection renders grade rows from `tbl_design_grade_map` active mappings; user can add more design lines.
- **AC-032** NOS validations identical to Inward (integer > 0; blank/zero skipped; RULE-015).
- **AC-033** On save, stock ledger decreases per (design, grade, sales_date) atomically with header + lines persistence.

## F-009 — Trading Tiles Adjustment Form
**Sprint:** S2 · **Priority:** critical

Physical stock verification for a single design.

- **AC-034** Exactly one tile design per adjustment entry (single-select).
- **AC-035** Form blocks save when `stock_date > entry_date` (ERR-010).
- **AC-036** On design selection with `stock_date` set, grade rows render with `software_closing_balance` pulled from the stock ledger as of `stock_date`.
- **AC-037** `physical_cb` required for every grade row; integer >= 0 (zero valid) (ERR-009).
- **AC-038** `difference = physical_cb - software_closing_balance` computed live; can be negative.
- **AC-039** On save, difference applied per grade row to the stock ledger atomically with header + lines persistence.
- **AC-040** If selected design has no active grade combinations, line entry blocked and ERR-012 shown.

## F-010 — Stock Dashboard
**Sprint:** S3 · **Priority:** critical

Date-filtered view of Opening / Inward / Outward / Adjust / Closing per design-grade.

- **AC-041** Selecting a date returns one row per (active design, active grade) with Opening/Inward/Outward/Adjust/Closing per FORMULA-001.
- **AC-042** First month of system use: Opening = 0 (FORMULA-002).
- **AC-043** On first day of any subsequent month: Opening = Closing of last day of previous month, no manual action.
- **AC-044** Closing for any date = Opening + cumulative Inward - cumulative Outward + cumulative Adjust within current month up to that date.
- **AC-045** Dashboard response sub-second for any single date with up to 12 months of transactions. *(non-testable in CI)*

## F-011 — Sales Report
**Sprint:** S3 · **Priority:** critical

Consolidation + Transaction views shown simultaneously with multi-select filters.

- **AC-046** All filters optional and multi-select; no filters = full dataset (RULE-018).
- **AC-047** Consolidation groups by `design_id + grade_id`, sums nos, orders by design_name ASC then grade_code ASC (RULE-019 / FORMULA-004).
- **AC-048** Transaction Report returns each sales line matching filters, ordered by `sales_date` ASC (RULE-020).
- **AC-049** Both sections render together on every filter apply — no toggle, no tab, Consolidation first.
- **AC-050** Sum of Numbers across Transaction Report equals sum in Consolidation Report for the same filter set.

## F-012 — Monthly Stock Carry-Forward
**Sprint:** S3 · **Priority:** critical

Automated: closing balance of Month N → opening balance of Month N+1, no manual operation.

- **AC-051** First transaction touching a (design, grade) in Month N+1: Opening = Closing as of last day of Month N (FORMULA-002).
- **AC-052** No prior month data for a (design, grade): Opening = 0 (RULE-012).
- **AC-053** Back-dated transaction inside the 7-day window straddling a month boundary leaves carry-forward correct.

## Constraints
- Transaction dates restricted to today and up to 7 days prior
- Adjustment Form: single design per entry
- Trading Size-Design Master separate from manufactured-tile designs
- No user authentication in V1
- Grade rows derive from `tbl_design_grade_map` active rows only

## Non-Functional
| Category | Requirement |
|---|---|
| Performance | Dashboard sub-second per date; form save < 500 ms; Sales Report < 2s for 1 year unfiltered |
| Security | V1 no auth — deploy on trusted internal network; server-side validation on all inputs |
| Scalability | Single tenant, single-digit concurrent users; row-level locking on stock ledger |
| Accessibility | Keyboard-navigable; required-field highlighting on save error |

## Edge Cases
- Design selected on Inward/Sales but has zero active grade mappings — line cannot be entered (ERR-012)
- Adjustment with `physical_cb = 0` against `software_cb = N` — valid, applies -N difference
- Back-dated transaction crossing a month boundary — both months' opening/closing remain correct
- User deactivates a Design-Grade mapping AFTER transactions exist — history preserved, only future forms hide the grade
- Concurrent saves on the same (design, grade) — must serialize via row-level lock on stock ledger

## Non-Goals (V1)

- Pricing, invoicing, payment tracking
- Manufacturing tiles module
- Inward Report
